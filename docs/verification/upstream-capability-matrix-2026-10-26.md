# Upstream capability completeness matrix

Status: **Partial. No full integration, native/Web AutoMix parity or publication claim.**

This maps the explicit platform capability list in the full goal to current implementation paths, supporting test sources and missing acceptance evidence. It replaces the assumption that a complete path inventory proves capability completeness. The hash-bound audit JSON is retained outside source in `.work/party-runtime-20261026/capability-matrix.json`.

There are 64 broad capability entries across seven groups, referencing 191 actual implementation paths. Every source/test selector resolves to an existing file. Supporting JVM evidence references 130 archived suite XML files across their recorded lanes; this is neither 130 distinct features nor a sum of current executions. The 26 October peak/cache report describes which shared tasks were reused and which JVMs actually executed.

All broad entries remain Partial because source integration and some automated assertions exist while the listed runtime, physical or publication conditions remain unverified. That does not mean the implementation is a placeholder. Specific accepted Surface issues are separately recorded below. A passing supporting test does not prove every behavior in a broad row.

Current Web verification executes 213 app tests plus nine shared bridge tests, all passing, recursive type checks and app/Chrome/Firefox builds. Seven separate real-browser message scenarios pass against the corrected bridge; they are not installed-extension/provider playback. The [Web lifecycle and scheduling report](web-lifecycle-and-automix-ownership-2026-10-26.md) records reproduced failures, actual changes and verification scope.

The [preparation/gain follow-up](web-preparation-and-gain-2026-10-26.md) adds eleven bounded-preparation and nine gain regressions, actual normal/fallback/pause/restart/WASM loop rendering at observed 48 and 44.1 kHz, and reusable browser test commands. Real OfflineAudioContext evidence removes early incoming gain without changing the intended fade. Generated PCM and a closed context do not establish provider/physical/listening parity; the observed ownership delay is corrected by the [audio-clock follow-up](web-handoff-clock-2026-10-26.md); full lyric UI alignment remains open.

The [membership follow-up](web-party-membership-2026-10-26.md) reproduces six stale-result failures in the actual Web membership store and verifies 18 cases after generation/identity guards. Fresh backend tests/vet pass separately. Controlled transport and server checks do not establish physical mixed-client synchronization.

The [real local runtime check](web-party-runtime-2026-10-26.md) executes the production Web store against actual Go REST/WebSocket handlers with a protocol peer. Membership, clock, queue/track, remote seek, host-only refusal/unlock, duplicate queue needle, reconnect, kick and leave pass. The ordinary suite skips this opt-in case; the source command executes it separately. This still is not installed Kotlin-client playback.

Repository-relative paths below refer to the approved nested source root, not the outdated outer copy or clean clone. No `.work` metadata, credentials, generated output or runtime profile is proposed for upload.
